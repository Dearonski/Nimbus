# Nimbus — план первой версии

Нативный SoundCloud-плеер для macOS: быстрый, красивый, с очередью, системным Now Playing и мини-плеером в меню-баре — то, чего нет в вебе.

**Вердикт по жизнеспособности:** реализуемо как личное / open-source приложение; **не** реализуемо как продукт в Mac App Store или платный клиент. Технический эталон уже существует — [Nuage](https://github.com/lbrndnr/nuage-macos) (живой SwiftUI-клиент, GPL-3, api-v2).

> Составлено на основе исследования 2026-07-09 (десяток проверяющих агентов + адверсариальная перепроверка ключевых фактов по первоисточникам). Все версии/факты проверены вживую на указанную дату.

---

## 1. Что изменилось и ломает наивный план

- **Только AAC поверх HLS.** Прогрессивный MP3 (`http_mp3_128_url`) убран ~31.12.2025. Осталось `hls_aac_160_url` / `hls_aac_96_url` — плейлисты `.m3u8`. «Скачал mp3 и играешь» больше не работает: мы HLS-клиент.
- **HLS подписан CloudFront и живёт ~5 минут.** Поток даёт 401/403 через ~5 мин. На треках длиннее 5 мин нужно **переполучать** плейлист во время игры. Это главное инженерное ограничение плеера.
- **Официальный API снова открыт — но платный.** С мая 2026 self-service регистрация приложения работает, но требует подписки **Artist Pro у разработчика** (разово, для тебя — не для каждого юзера). OAuth 2.1 + PKCE, лимит **15 000** проигрываний / 24 ч на client_id, refresh-токены одноразовые.
- **Оффлайн-кэш прямо запрещён ToS.** API Terms: никакого офлайн-доступа, даже временных загрузок «для прослушивания офлайн»; кэш только на время сессии.

## 2. Развилка: авторизация и получение потока

Ключевое архитектурное решение — **развязать** слой авторизации и движок стриминга.

| | Внутренний api-v2 **(выбран для v1)** | Официальный OAuth 2.1 (fallback) |
|---|---|---|
| Функционал | Полный: `/me/library/all`, лента, история, related | Беднее (история/библиотека) |
| Стоимость | Бесплатно, любой залогиненный юзер | Нужна подписка Artist Pro у разработчика |
| Логин | WKWebView + cookie `oauth_token` (тянет Google-SSO) | PKCE authorization_code |
| Минусы | Нарушает ToS; хрупко (ротация client_id) | Потолок 15k проигрываний/сутки; редиз-стойкий |

Плеер одинаков в обоих случаях: `media.transcodings` → выбрать AAC-HLS пресет → `GET transcoding.url?client_id&track_authorization` → подписанный `.m3u8` → `AVPlayer`. Разница только в источнике токена.

## 3. Аудио-движок и правда про gapless

Сегменты SoundCloud — ADTS/TS AAC **без edit-lists**, поэтому ни один «URL-in» путь Apple не подрежет прайминг за нас (≈2112 сэмплов ≈48 мс тишины на стыке).

- **v1:** `AVQueuePlayer` поверх `hls_aac_160_url` — предбуферизация, без паузы на переходе, «на слух» бесшовно + короткий кроссфейд там, где важен эффект (альбомы, миксы). Бесплатно даёт AirPlay 2, Now Playing и адаптивный HLS.
- **v2 (настоящий gapless):** кастом на `AVSampleBufferAudioRenderer` + `AVSampleBufferRenderSynchronizer` — свой демукс ADTS, декод, тримминг прайминга через `kCMSampleBufferAttachmentKey_TrimDurationAtStart`. Сохраняет Now Playing / AirPlay. Недели работы — не в v1.

**Now Playing на macOS:** нет `AVAudioSession`. Чтобы стать «текущим» приложением и ловить медиа-клавиши — вручную `MPNowPlayingInfoCenter.default().playbackState = .playing` + заполнять `nowPlayingInfo`, зарегистрировать `MPRemoteCommandCenter`. Движок на `AVAudioEngine`/`AVPlayer` система подхватывает. Локдаун MediaRemote (15.4+) не мешает — он про *чтение* чужого Now Playing.

## 4. Оффлайн-кэш (в v1, personal-use)

Оставлен в v1 осознанно. Честно: **фича нарушает ToS** SoundCloud. Поэтому — строго personal-use posture: OSS, без бинарных релизов именно с этой функцией, атрибуция на месте.

**Технический путь:** `AVAssetResourceLoaderDelegate` **не кэширует** HLS-сегменты — только редиректит (ошибка `-12881`, сегменты грузит `mediaserverd` вне URL Loading System). Значит: скачать сегменты `.m3u8` и ремукснуть passthrough через `AVAssetWriter` в один `.m4a` (без перекодирования), сложить в `Application Support` внутри контейнера, играть как локальный файл. Опционально — почанковое AES-GCM шифрование. Индекс загрузок и LRU-эвикция — в GRDB. Метаданные/артворк кэшируются всегда (это допустимо).

## 5. Стек и целевая ОС

Deployment target — **macOS 15** (не 26.5): все Liquid Glass API — это macOS 26.0, а 26.5 отрезает пользователей зря. Собирать SDK 26; стандартные контролы сами получают Liquid Glass на 26 и классический вид на 15 (≈85% Маков в охвате).

| Слой | Выбор | Версия (сер. 2026) |
|---|---|---|
| Хранилище | **GRDB.swift** (SQLite, FTS5-поиск, ValueObservation) | 7.11.1 |
| Конкурентность | Swift 6 mode + Approachable Concurrency (`defaultIsolation = MainActor`) | Swift 6.2 |
| Аудио-состояние | **swift-atomics** для обмена с RT-потоком | 1.3.1 |
| Артворк | **Nuke** (LazyImage, диск+память) | 13.0.6 |
| Глоб. хоткеи | **KeyboardShortcuts** (Carbon, без прав доступа) | 3.0.1 |
| Токен | свой ~100-строчный `SecItem`-обёртка (KeychainAccess мёртв с 2020) | — |
| Сеть | URLSession async/await (без Alamofire) | — |
| Волна | **DSWaveformImage** (принимает `[Float]`) или свой Canvas | 14.5.0 |
| Медиа-контролы | MPNowPlayingInfoCenter + MPRemoteCommandCenter | системные |

## 6. Вехи v1 — от риска к полировке

Порядок неслучаен: сначала «ходячий скелет», проверяющий самые рискованные допущения. Оценки грубые, для соло-разработчика.

### M0 — Ходячий скелет (~несколько вечеров)
WKWebView-логин → харвест `oauth_token` → скрейп `client_id` → `/resolve` одного трека → резолв transcoding → `AVPlayer` играет HLS. Плюс механизм ре-резолва плейлиста до истечения 5 мин.
**Done:** трек длиннее 5 минут доигрывает до конца без 403; логин переживает перезапуск.
_Самое рискованное — пока не работает, остальное косметика._

### M1 — Библиотека (~1 неделя)
Likes, плейлисты, история через api-v2 с пагинацией. Оболочка: `NavigationSplitView` (сайдбар + инспектор), Liquid Glass по умолчанию, артворк через Nuke, метаданные в GRDB.
**Done:** прокрутка 5–10k треков плавная; поиск по локальной базе (FTS5) мгновенный.

### M2 — Плеер и очередь (~1–1.5 недели)
`AVQueuePlayer`, очередь с drag-and-drop (`List.onMove` + `.onInsert`), скраббер по `waveform_url` с таймлайн-комментами, Now Playing + медиа-клавиши, полный shuffle всей очереди.
**Done:** F7/F8/F9 и Control Center управляют Nimbus; перетаскивание трека из плейлиста в очередь работает.

### M3 — Мини-плеер в меню-баре (~4–5 дней)
`NSStatusItem` + `NSPanel` (богаче, чем `MenuBarExtra(.window)`), переключение activation policy (`.regular`/`.accessory`), close = hide, глобальные хоткеи.
**Done:** приложение живёт в меню-баре без иконки в доке; мини-плеер управляет воспроизведением.

### M4 — Оффлайн-загрузки (~1 неделя, personal-use)
Скачивание сегментов HLS + passthrough-ремукс через `AVAssetWriter` в `.m4a`, индекс загрузок и LRU-эвикция в GRDB, опциональное почанковое AES-GCM, воспроизведение из локального файла.
**Done:** трек проигрывается в самолётном режиме; лимит кэша соблюдается, старое вытесняется.

### M5 — Полировка (~3–5 дней)
Поиск (треки/юзеры/плейлисты), тема по доминантным цветам обложки (MeshGradient), клавиатурная навигация, обработка протухших токенов и ротации client_id на лету.
**Done:** токен истёк во время игры → тихий ре-логин без падения; VoiceOver читает скраббер.

## 7. Дифференциаторы против веб-плеера (по value/cost)

1. **Полная очередь с drag-and-drop** — в вебе управление очередью убогое.
2. **Настоящий shuffle всего плейлиста** — веб рандомит только ~20–30 подгруженных «Next up».
3. **Системный Now Playing + медиа-клавиши** — F7/F8/F9, AirPods, Control Center.
4. **Мини-плеер в меню-баре** — управление, не открывая окно.
5. **Нативная лёгкость и скорость** — против тяжёлого веб-UI.
6. **«Gapless-ощущение» через кроссфейд** — закрывает боль на альбомах/миксах.

## 8. Вырезано из v1

- Настоящий sample-accurate gapless → пока кроссфейд, кастомный движок в v2.
- Официальный OAuth-путь → подключаемый fallback, не основной.
- Go+ 256k AAC, эквалайзер, sleep timer, AirPlay-пикер → потом.
- Last.fm scrobble, постинг комментов, загрузки-аплоады → вне первой версии.

## 9. Риски

| Риск | Уровень | Смягчение |
|---|---|---|
| Истечение подписанного HLS ~5 мин посреди трека | Высокий | Ре-резолв плейлиста до истечения (как `RefreshableHls` в NewPipe) |
| Ротация client_id / изменения api-v2 → тихая поломка | Высокий | Авто-ре-скрейп по 401/403; следить за master yt-dlp как за канарейкой |
| Нарушение ToS (внутренний API, оффлайн-кэш) | Средний | OSS, personal-use, без бинарных релизов офлайна, атрибуция SoundCloud |
| Потолок 15k проигрываний/сутки при широкой раздаче | Средний | Для api-v2 неактуально; для официального — bring-your-own client_id |
| Отклонение в Mac App Store (гайдлайн 5.2.2) | Средний | Раздача через DMG / Homebrew cask / GitHub Releases, как Nuage |
| Сложность настоящего gapless на TS/ADTS | Низкий | Не блокирует v1: бесшовный AVQueuePlayer + кроссфейд |
